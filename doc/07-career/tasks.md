# 长期任务：求职准备与持续学习

## 岗位定位

- [ ] 简历目标岗位统一为 AI 应用开发工程师/大模型应用工程师。
- [ ] 强调“8 年 Java 企业工程经验 + AI 应用落地”，不将自己包装成初级算法工程师。
- [ ] 将 RAG、Agent、评测、安全、成本和稳定性写成可验证成果。
- [ ] 每条项目描述包含业务问题、个人职责、技术方案、量化结果和复盘。

## 面试能力

- [ ] 能讲清 Prompt、RAG、微调和 Agent 的选择边界。
- [ ] 能讲清向量检索、BM25、混合检索和 Rerank。
- [ ] 能设计企业知识权限和多租户隔离。
- [ ] 能设计工具调用的审批、幂等、补偿和审计。
- [ ] 能说明如何评测幻觉、忠实度、检索召回和拒答。
- [ ] 能说明如何监控 Token、延迟、成本和模型故障。
- [ ] 能识别 Prompt Injection、工具越权和数据泄露风险。
- [ ] 能完成一个 AI 系统设计题，而不只是框架 API 问答。

## 持续学习规则

- [ ] 每月只选择一个新模型或新框架做对比实验。
- [ ] 优先阅读官方文档、规范和高质量论文。
- [ ] 新技术只有在解决明确问题并通过评测后才进入主项目。
- [ ] 每月更新一次依赖，不盲目追逐每日版本。
- [ ] 每季度复查 20～30 个目标岗位 JD，更新技能差距清单。
- [ ] 保留实验日志，记录假设、配置、数据、结果和结论。

## 暂不作为主线

- [ ] 多 Agent：只有单 Agent 和 Workflow 明确不足时再学习。
- [ ] 大模型预训练：除非后续转向算法/训练岗位。
- [ ] CUDA/分布式训练：作为 AI 平台或算法方向的后续选修。
- [ ] LoRA 微调：在 RAG/Prompt 无法解决稳定需求时做专项实验。
- [ ] Kubernetes 深入运维：完成 Docker Compose 交付后再扩展。
