# 第 14～17 周：Tool、Workflow、Agent 与 MCP

## 阶段目标

让模型在受控边界内完成业务任务，优先使用确定性工作流，避免为了 Agent 而 Agent。

## 第 14 周：Tool Calling 工程化

- [ ] 区分只读工具、低风险写工具和高风险写工具。
- [ ] 为工具定义名称、用途、参数、权限、超时和风险等级。
- [ ] 实现工具入参校验、输出裁剪和敏感字段过滤。
- [ ] 为写操作增加幂等键。
- [ ] 记录工具调用审计日志。
- [ ] 验证模型不能调用未授权工具。

## 第 15 周：确定性 Workflow

- [ ] 使用状态机或显式步骤实现一个业务工作流。
- [ ] 支持步骤状态持久化和失败后恢复。
- [ ] 实现超时、有限重试、补偿和取消。
- [ ] 对高风险动作增加人工审批节点。
- [ ] 处理审批通过、拒绝和超时三种结果。
- [ ] 证明重复提交不会产生重复业务操作。

## 第 16 周：单 Agent

- [ ] 理解 ReAct 的 Observation/Thought/Action 工作方式，但不向终端用户暴露内部推理。
- [ ] 实现一个能够在多个只读工具间选择的 Agent。
- [ ] 限制最大步骤数、最大 Token 和总执行时间。
- [ ] 实现循环检测和重复工具调用保护。
- [ ] 将确定性步骤保留在业务服务中，而不是全部交给模型决定。
- [ ] 对 Agent 成功率、平均步骤数、延迟和成本进行评测。

## 第 17 周：MCP

- [ ] 理解 MCP Host、Client、Server 的关系。
- [ ] 理解 Tool、Resource、Prompt 三种核心原语。
- [ ] 使用 Spring AI 创建一个最小 MCP Server。
- [ ] 暴露一个只读 Resource 和一个只读 Tool。
- [ ] 使用 MCP Client 发现并调用工具。
- [ ] 为远程 MCP 连接设计认证、授权和超时。
- [ ] 记录 MCP 与普通 REST Tool Calling 的选择差异。

## 完成标准

- [ ] Agent 只能使用授权工具。
- [ ] 高风险操作必须人工审批。
- [ ] 任务失败可恢复、可重试、可审计。
- [ ] 能说明什么时候使用 Workflow，什么时候才需要 Agent。
- [ ] 暂不以多 Agent 作为必做项；只有单 Agent 无法满足明确需求时才进入多 Agent。
