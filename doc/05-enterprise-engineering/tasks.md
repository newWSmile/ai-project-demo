# 第 18～21 周：企业工程化、评测与安全

## 阶段目标

把“能运行的 AI Demo”提升为“具备企业落地基本条件的系统”。

## 第 18 周：架构与可靠性

- [ ] 设计模型适配层和模型路由策略。
- [ ] 实现限流、舱壁隔离、熔断、重试和降级。
- [ ] 区分同步请求、流式请求和异步长任务。
- [ ] 使用消息队列或任务表处理文档解析/索引任务。
- [ ] 实现会话、任务和索引状态的持久化。
- [ ] 设计服务关闭和任务恢复策略。

## 第 19 周：安全与权限

- [ ] 实现登录、RBAC 和多租户隔离。
- [ ] 对上传文件做类型、大小、恶意内容和路径检查。
- [ ] 对敏感字段做脱敏或阻断。
- [ ] 测试直接 Prompt Injection。
- [ ] 测试文档中的间接 Prompt Injection。
- [ ] 测试工具越权、参数注入和数据外泄。
- [ ] 为高风险输出增加校验或人工复核。
- [ ] 建立不少于 20 条安全回归用例。

## 第 20 周：可观测性与成本

- [ ] 使用 Micrometer/OpenTelemetry 记录 Trace。
- [ ] 关联用户请求、模型调用、检索、Rerank 和工具调用。
- [ ] 记录首 Token 延迟、总延迟、错误率和并发数。
- [ ] 记录输入/输出 Token 和估算成本。
- [ ] 默认不记录原始 Prompt 和回答中的敏感内容。
- [ ] 建立 Prometheus/Grafana 仪表盘。
- [ ] 为异常失败率、延迟和成本突增设计告警。

## 第 21 周：评测与发布治理

- [ ] 统一 Prompt、模型、Embedding、Rerank、知识库和代码版本。
- [ ] 模型或 Prompt 更新时自动运行离线评测。
- [ ] 设置最低质量门槛，未达标则阻止发布。
- [ ] 实现用户点赞/点踩和问题反馈记录。
- [ ] 区分离线评测、在线指标和业务指标。
- [ ] 设计灰度发布与快速回滚流程。
- [ ] 对典型流量执行基础压测。

## 完成标准

- [ ] 单一模型故障不会直接导致整个系统不可用。
- [ ] 关键调用可通过 Trace 定位。
- [ ] 能回答“本次请求为什么贵、慢或失败”。
- [ ] 权限、安全、质量回归均有自动测试或可重复步骤。
