# 第 9～13 周：企业级 RAG

## 阶段目标

构建可评测、可引用、可拒答、支持权限和增量更新的企业知识库，而不是简单的“上传 PDF 聊天”。

## 第 9 周：文档摄取

- [ ] 支持 PDF、DOCX、Markdown、HTML、TXT 中至少三种格式。
- [ ] 设计原始文件、解析文本、Chunk、索引记录之间的数据模型。
- [ ] 保存文档来源、版本、页码/章节、租户、权限等元数据。
- [ ] 处理空文档、扫描件、乱码、表格和重复内容。
- [ ] 实现固定长度和按标题/段落切片两种策略。
- [ ] 对两种切片策略生成可对比的数据。

## 第 10 周：向量检索

- [ ] 使用 Embedding 模型生成向量。
- [ ] 使用 PostgreSQL + pgvector 保存和查询向量。
- [ ] 理解 Top-K、距离函数和相似度阈值。
- [ ] 对 Chunk 大小、Overlap、Top-K 进行对比实验。
- [ ] 在回答中返回文档名、章节、页码和原文片段。
- [ ] 当证据不足时返回拒答，而不是让模型自由补全。

## 第 11 周：混合检索与 Rerank

- [ ] 使用 OpenSearch/Elasticsearch 建立 BM25 索引。
- [ ] 实现关键词检索和向量检索。
- [ ] 实现一种混合排序/融合策略。
- [ ] 接入 Rerank 模型或实现可替换的重排序接口。
- [ ] 实现 Query Rewrite。
- [ ] 实现 Multi-Query，并评估收益与额外成本。
- [ ] 比较“纯向量、纯 BM25、混合、混合 + Rerank”四组结果。

## 第 12 周：权限、版本和索引生命周期

- [ ] 实现租户级过滤。
- [ ] 实现部门/角色/用户级文档权限过滤。
- [ ] 确保权限过滤发生在检索阶段，而不是仅在答案展示阶段。
- [ ] 实现文档新增、更新、删除后的增量索引。
- [ ] 实现索引失败重试和状态记录。
- [ ] 处理旧版本 Chunk 与向量的清理。
- [ ] 编写跨租户和越权检索测试。

## 第 13 周：RAG 评测

- [ ] 建立不少于 50 条问题、标准答案、证据文档三元组。
- [ ] 计算 Recall@K、Precision@K。
- [ ] 理解并选择性实现 MRR/NDCG。
- [ ] 评估答案相关性、忠实度和引用准确率。
- [ ] 单独统计可回答问题和不可回答问题的拒答表现。
- [ ] 保存各检索策略的基线结果和改进结果。
- [ ] 将评测脚本加入 CI 或一键命令。

## 完成标准

- [ ] 回答能够定位到真实原文。
- [ ] 没有权限的文档不会进入模型上下文。
- [ ] RAG 优化有评测数据证明，而不是凭主观感觉。
- [ ] 文档更新后索引可以正确增量刷新。
