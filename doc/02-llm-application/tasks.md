# 第 6～8 周：LLM API 与 Prompt 工程

## 阶段目标

完成一个具备结构化输出、流式响应、会话、工具调用和基础可靠性的大模型应用服务。

## 知识笔记

- [模型供应商适配层与对话记忆](./model-adapter-and-conversation-memory.md)
- [大模型 Token 预算管理](./token-budget.md)

## 第 6 周：Prompt 和结构化输出

- [ ] 掌握 System、User、Assistant 消息的职责。
- [ ] 编写 Zero-shot、Few-shot 和带约束的 Prompt。
- [ ] 使用模板管理变量，禁止在业务代码中散落长 Prompt。
- [ ] 使用 JSON Schema/Java 类型实现结构化输出。
- [ ] 对结构化输出增加校验和有限次数修复。
- [ ] 为 Prompt 建立名称、版本、用途和变更记录。
- [ ] 编写至少 20 条 Prompt 回归样例。

## 第 7 周：会话和工具调用

- [ ] 实现 conversationId 与多轮消息持久化。
- [ ] 区分短期对话历史与长期用户记忆。
- [ ] 实现一个只读查询工具。
- [ ] 为工具参数定义严格 Schema。
- [ ] 处理工具超时、空结果、异常和模型重复调用。
- [ ] 验证模型不能直接伪造工具结果。
- [ ] 对工具调用记录输入、输出、耗时和调用人。

## 第 8 周：可靠性和模型适配

- [ ] 抽象模型提供方接口，避免业务层绑定单一厂商。
- [ ] 至少接入两个兼容模型并支持配置切换。
- [ ] 实现连接超时、读取超时和有限重试。
- [ ] 对 429/5xx 使用退避策略，避免无边界重试。
- [ ] 实现请求级 Token 上限和用户级配额。
- [ ] 记录首 Token 延迟、总延迟、输入/输出 Token 和失败原因。
- [ ] 了解 Prompt Caching 和语义缓存的差异。

## 完成标准

- [ ] API 同时支持同步、流式和结构化输出。
- [ ] 工具调用失败不会导致无限循环。
- [ ] 切换模型无需修改业务代码。
- [ ] Prompt 回归样例可以自动运行并输出报告。
