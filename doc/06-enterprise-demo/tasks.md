# 第 22～24 周：Enterprise Copilot 交付

## 阶段目标

完成可演示、可部署、可评测、可讲解的企业级作品集项目。

## 第 22 周：业务闭环整合

- [ ] 管理员能够上传、更新、停用和删除知识文档。
- [ ] 用户只能检索有权限的知识。
- [ ] 问答返回引用，证据不足时拒答。
- [ ] Agent 可以查询模拟业务数据。
- [ ] Agent 可以生成任务草稿。
- [ ] 用户确认后才能执行写操作。
- [ ] 所有关键操作均有审计记录。
- [ ] 管理端能够查看知识处理和索引状态。

## 第 23 周：测试、压测和部署

- [ ] 完成单元测试、集成测试和 Testcontainers 测试。
- [ ] 完成 RAG 离线评测。
- [ ] 完成 Agent 任务成功率评测。
- [ ] 完成权限与安全回归。
- [ ] 完成模型超时、限流、不可用的故障演练。
- [ ] 执行基础并发压测并记录 P50/P95/P99。
- [ ] 编写 Dockerfile 和 Docker Compose。
- [ ] 在全新环境验证一键启动。

## 第 24 周：作品集和面试材料

- [ ] 完成项目 README。
- [ ] 绘制系统架构图、RAG 数据流和 Agent 执行流程。
- [ ] 编写主要 ADR：模型、框架、数据库、检索和安全选型。
- [ ] 输出基线与优化后的评测对比表。
- [ ] 记录已知限制和后续优化方向。
- [ ] 准备 5～10 分钟演示脚本。
- [ ] 录制一段完整演示视频。
- [ ] 将项目经历整理为简历 STAR 描述。
- [ ] 准备至少 20 个与项目相关的面试问题及答案。

## 最终发布门槛

- [ ] 不少于 50 条 RAG 黄金评测数据。
- [ ] 不少于 20 条安全/越权测试。
- [ ] 跨租户检索测试全部通过。
- [ ] 写工具全部经过审批和幂等控制。
- [ ] 可查询 Token、成本、延迟和失败原因。
- [ ] 模型切换后可以一键运行回归评测。
- [ ] Docker Compose 可复现启动。
- [ ] 文档能够让其他开发者独立运行项目。
